# AI Investment Research System

A Python pipeline that takes a listed company (US or India) and produces a structured
investment research report: financial analysis with peer comparison, macroeconomic context,
a technical price picture, and a check of whether key macro claims are supported by sources.

The system describes and explains. It does **not** issue buy/sell recommendations.

> **Disclaimer:** This is a personal learning project, not investment advice.
> Outputs can contain errors (see Known Limitations). Always do your own research.

## What happens in one run

| Step | Module | What it does | Data source |
|---|---|---|---|
| 1 | Company Identification | Confirms ticker, exchange, sector, industry | yfinance |
| 2 | Financial Analysis | Ratios, peer selection and comparison, rule-based thesis | yfinance, Tavily |
| 3 | Macro Analysis | Market-level context (US or India) and sector themes | FRED, Tavily, Claude |
| 4 | Technical Analysis | Describes the price and trend picture (no forecasts) | yfinance |
| 5 | Source Verification | Searches the web to check macro claims; labels each one | Tavily, Claude |
| 6 | Report Generation | Assembles a Markdown report in `outputs/` | - |
| 7 | Database | Saves the run, module statuses and versions | SQLite |

Steps run in sequence. The market (US or India) is detected from the ticker:
`.NS` / `.BO` listings are treated as India; everything else as US.

---

## Design principles

- **Deterministic pipeline, not an autonomous agent.** Python controls the order of steps.
  The LLM (Claude) is used for two judgment tasks only: macro interpretation and claim verification.
- **Judgment to the LLM, arithmetic to Python.** All ratios and comparisons are computed in code.
- **Leashed LLM calls.** Fixed role prompts, strict JSON output, low temperature, and code
  validation with a safe fallback if the response is malformed.
- **Graceful degradation.** Each module runs independently. One failure does not stop the run;
  the report shows what is missing. Only failure to identify the company stops a run.
- **Honest outputs.** "Not available" is shown as such, never as zero. Unverified claims are
  labelled, not hidden.
- **Traceability.** Every run is stored with each module's status and version number.

## Setup

Tested on Windows with Python 3.13.

```bash
git clone https://github.com/pulkitgautam-007/ai_investment_research.git
cd ai_investment_research
python -m venv venv
venv\Scripts\activate          # Mac/Linux: source venv/bin/activate
pip install -r requirements.txt
```

Then copy `.env.example`, rename the copy to `.env`, and add your keys:

| Key | Required? | Get it from |
|---|---|---|
| `TAVILY_API_KEY` | Yes | tavily.com (free tier available) |
| `ANTHROPIC_API_KEY` | Yes | console.anthropic.com (paid, small credit is enough) |
| `FRED_API_KEY` | Yes | fred.stlouisfed.org (free) |
| `NEWS_API_KEY` | No | Only used by the parked Research Agent |
| `FINNHUB_API_KEY` | No | Only used by the parked Research Agent |

## Usage

```bash
python main.py --ticker INFY.NS          # no questions asked (recommended)
python main.py Infosys                   # searches by name, you pick from a list
python main.py                           # asks for a company name
python main.py --ticker AAPL --verbose   # detailed module output
```

For Indian companies, use the NSE listing (e.g. `INFY.NS`).
The report is saved to `outputs/report_<company>_<date_time>.md`.
`main.py` returns exit code 0 if a report was created, 1 otherwise.

## Known limitations (v1)

Tested end-to-end on two companies (Infosys, Apple). Known issues, to be fixed in v2:

**Visible in reports**
- Peer selection can pick wrong companies (e.g. "HP" matched Helmerich & Payne, an oil
  driller, instead of HP Inc.), and some validated peers are dropped before data is fetched.
- When peer data is missing, a sentence can read "in line with the peer average of None".
- Very high ROE driven by share buybacks (e.g. Apple) is described as exceptional efficiency
  without noting the buyback effect.
- The scorecard shows a label such as "Positive - worth watching", which is closer to a
  verdict than the project intends.
- Peer data glitches (e.g. an implausible -98% revenue growth) are correctly excluded from
  averages, but the report does not tell the reader this.

**Coverage and data**
- Source verification checks about 5 claims per run (budget cap), not all extracted claims.
- "Contradicted" can mean sources define a market differently, not that a claim is false.
- Indian company financials are internally in USD; currency labels need correcting before
  absolute figures are added to reports.
